# 产品方向与验收路线

目标：Creator 3.8.8 优先，提供方便安装、可观察、可验证、易扩展的源码可见 MCP，个人非商业使用免费，商用与再分发须书面授权，详见 [许可说明](LICENSING.md)。Pro 公开功能作为需求参考，不以工具数量或未实测宣传作为验收标准。当前为 0.8.1 开发预览，尚未达到完整 Pro 功能对齐或“全面超越”。

2026-10-28 详细需求基线见 [Pro 功能分析与产品规格](PRO-CAPABILITY-ANALYSIS.md)。其中 R01–R24 为可跟踪需求，T01–T30 为代表任务验收目录；下表是概览，后续以该规格的阶段门槛和实际验证记录判断完成情况。

0.5.0 当前进展：预制体核心流程之后，已补资源依赖/反向引用、原生移动/复制/重导入、精确引用替换与恢复；8 类原生动画轨道、Spine 3.8 配置/运行事件；Web Desktop/Mobile 构建产物启动并验证动画与业务事件。详见 [资源、动画与构建](RESOURCE-ANIMATION-BUILD.md)。复杂变体、完整国际化/视觉回归、参考图、完整运行断言、SDK 原生构建、发行向导仍需完善；R04 不含完整 TS 检查/热重载保障，阶段 A 尚未全部完成。

0.7.0 当前进展：增加场景视图/参考图语义操作和控制面板，原生消息回读与真实 Creator 复测已通过；0.6.0 当前进展：增加五项字体/UI 专用操作与文字布局面板，真实保存重开/预览和面板输入已验收；compact 测量保留相同几何并减少返回数据。见 [字体与 UI](TYPOGRAPHY-UI.md)。这仍是有限规则检查，不代表全部 Pro 领域已完成。

0.8.0 进展：增加 `ui.layout` 语义操作和「UI 适配」面板，覆盖 Widget、Layout、ScrollView、Mask、SafeArea、BlockInputEvents 的补齐、配置、预检查、回读和移除；Creator 3.8.8 实时布局检查已通过。多分辨率视觉回归、业务滚动复用、主题/组件库仍需专用验收。

0.8.1 进展：完整扩展 ZIP 已含 MCP 服务与依赖，使用 Creator 自带运行环境。解压到 extensions、启用并复制客户端配置即可；实际 Windows Creator 3.8.8 的扩展替换/启用、配置生成和客户端读取场景已验证。其他系统的 Creator 集成与一键客户端配置仍待验收。

## 使用体验

新用户路径应为：安装一个扩展 → 打开控制台 → 选目标项目和客户端 → 检测环境 → 复制或明确授权后写入配置 → 执行一个可见的示例任务。当前已完成项目安装脚本、配置复制、连接状态、能力目录、UI 模板和操作记录；0.8.1 已补完整扩展 ZIP，含 MCP 服务与依赖，使用 Creator 自带运行环境；后续补项目选择器、兼容性诊断与卸载向导。

界面分为连接与项目、能力目录、模板、操作记录和设置。参数按需展开，失败显示具体步骤、已完成结果和修复方向；不显示虚假的“成功”或难以追溯的原始堆栈。开发版保留准确参数和请求 ID，便于贡献者定位。

核心无需注册、激活码或厂商云服务。连接本地编辑器的桥接不调用模型 API，不采集遥测；AI 客户端的模型服务和费用由用户自行选择。

## 为超出公开 Pro 范围设计的能力

已落地的基础：请求 ID 与超时状态、串行批量、跨步骤结果引用、参数预检查、默认摘要/字段投影、界面中的暂停编辑与高级入口开关。是否对方也具备这些能力，仍需实际 Pro 证据，不能宣称全部独有。

后续重点：可重放的任务计划、差异预览、依赖图、组件扩展注册、可复用项目模板、运行时交互测试、跨分辨率验收、持续集成构建检查、可导出的失败复现包。完整回滚必须按操作类别明确保障范围；资产与场景混合操作不能仅调用一次 undo 就宣称原子性。

## Token 与效率

默认只暴露 status/catalog/execute/observe 四个 MCP 工具；operation schema 按需读取。目录不为每个功能反复暴露完整描述。保留 legacy 模式兼容已有任务。减少往返靠批量执行和结果引用，减少返回靠摘要与字段投影，减少重复阅读靠增量事件和快照差异，截图按需获取。

当前基准：旧 30 工具 tools/list 的 UTF-8 JSON 为 18,508 字节；4 工具为 3,255 字节，减少 82.4%。这只是清单体积，不是 Token 数。`npm run benchmark:workflow` 已记录相同四项实际读取任务的调用次数/耗时/字节，并单列目录发现成本；没有模型真实用量时不换算 Token 或费用。

任务评测应同时记录正确率、模型输入/输出 Token（由客户端提供）、调用次数、耗时、失败恢复和最终产物。必须在相同任务、资源、版本与模型条件下比较，才可以判断是否优于 Pro。

## 交付阶段

1. **0.2 开发预览**：面板、精简工具、批量执行、UI 起步模板、结构验证、源码发行基础。当前已实现；仍需要更多用户与平台测试。
2. **0.3 游戏界面流程**：UI 完整自适应、脚本/事件/引用、预制体和资源依赖；验收一个可交互菜单与背包界面。
3. **0.4 动画与运行验证**：动画/Spine、运行日志、交互、自动修复；验收一个有角色动画的小型游戏。
4. **0.5 构建与发行**：构建产物、跨平台连接、安装/升级/卸载、扩展机制与任务回归，达到可公开推荐的版本。

每阶段都有独立可运行产物。路线图不等于当前已提供功能，公开源码发布时保留这一区分。
