## UI 模板不可见问题的修复与更正

此前 Canvas 搜索直接遍历 `cc.director.getScene()`，把 Creator 隐藏的 `Reference-Image-Canvas` 当成项目 Canvas。模板创建与读取能完成，但节点不在正常层级、不进入场景保存；此前 UI 与快照测试因此存在假阳性，不能作为可见 UI 的验收依据。

现改为使用 `scene/query-node-tree` 的项目节点白名单，排除整个编辑器辅助子树。没有真实 Canvas 时，从本机 Creator 内置资源创建 Canvas 和 UI 相机；显式指定辅助层父节点会拒绝。生成后检查全部节点确实属于项目层级，面板会选中、切换 2D 并聚焦，且提供重新定位按钮。

新增 `npm run test:live:ui` 在一次性场景中完成：空项目 dry-run 无修改、拒绝辅助 Canvas、自动创建 Canvas/相机、原生面板消息生成与选中定位、保存后关闭重开仍保留节点、dialog/hud 复用真实 Canvas。6 项真实检查已通过，截图人工确认主菜单文字可见。新自动检查总计 17 项通过，覆盖项目边界与辅助 Canvas 回归。证据为 `artifacts/live-ui-check.json`、`artifacts/ui-regression-menu.png`。

以上验证调用了面板使用的原生消息入口，仍未把“所有面板按钮的系统鼠标点击”作为已完成验收项。
